# 이 디렉토리 = 본선 작업 공간

## 지금 무슨 상황인가

**NYPC 2026 AI 부문 본선 진행 중.** 1대1 턴제 게임을 플레이하는 AI 프로그램을
만들어 제출하면, 다른 참가자들이 만든 AI와 대전시켜 승패로 순위를 매긴다.
**남들 것보다 강한 AI를 만드는 것이 유일한 목표다.**

- **게임 규칙은 본선이 시작될 때 공개된다.** 주최측이 규칙과 함께 **게임 시뮬레이션
  코드(참조 구현)**를 제공한다. 예선 게임과 완전히 다를 수 있다.
- 규칙 공개 후 **6시간** 안에: 환경 구현 → AI 설계 → 학습 → 제출.
- 그래서 이 디렉토리가 있다: **게임과 무관한 학습 파이프라인은 이미 다 만들어져
  있고 테스트도 통과한 상태다** (`rlkit/`). 그날 새로 쓰는 것은 게임 환경,
  관측/행동/보상 설계, 네트워크 구조뿐이다.

## 세션 시작 시 사용자에게 받을 것

아래 네 가지는 **사용자가 알려준다.** 추측하거나 탐지하려 하지 말고, 없으면 요청하라.

1. **게임 규칙** — 규칙 문서 + 주최측 **참조 구현 코드**
2. **파이썬 가상환경 경로** — 이후 모든 명령을 이 인터프리터로 실행한다
3. **학습 서버 CPU 스레드 수**
4. **학습 서버 GPU 스펙** — 모델명, 장수, 장당 VRAM

받는 즉시 **아래 블록을 이 파일에서 직접 수정해 채워 넣어라.** 세션이 길어지거나
컨텍스트가 압축돼도 이 값들이 남아 있어야 한다.

```
[환경 — 사용자에게 받아서 채울 것]
python(학습서버): (미확인, 서버 접속 시 확인) — GPU 노드 venv 경로
python(로컬)    : D:\applications\anaconda3\envs\nypc\python.exe
CPU      : 학습서버 128 스레드
GPU      : 학습서버 RTX 3090 x6 (24GB each) / RAM 503GB
           로컬(개발) RTX 2060 laptop 1장 — 디버깅/스모크 테스트용
규칙/참조: testing-tool2.py (신규 참조 구현, 최상위 디렉토리)
           구 참조 구현은 testing-tool.py (예선) — diff 대상
```

- 개발 머신과 학습 서버가 다를 수 있다. **다르면 둘 다 적어라.**
- 이 값들이 정해지기 전에는 `B`, `--gpus`, `instance_workers`를 임의로 확정하지
  마라 (계획 4단계). 그전 실험은 작은 값으로 돌린다.
- 환경이 살아 있는지 확인하는 한 줄:
  ```bash
  <python> -c "import torch;print(torch.__version__, torch.cuda.is_available(), torch.cuda.device_count())"
  ```

## 팀의 진행 계획 (이 순서로 움직인다)

| 단계 | 누가 | 무엇 |
|---|---|---|
| **1** | **Claude** | 주최측 참조 구현 + 규칙 설명을 받아 **GPU 배치 환경**을 만들고, 참조와 **정합성 검증**까지 끝낸다 → `PORTING_GUIDE.md` |
| **2** | 사람 (1단계와 **병렬**) | observation / action space / reward / 네트워크 구조 설계 |
| **3** | **Claude** | 2단계 설계를 받아 **`Task` + `Policy`** 구현 → PPO 학습 코드 완성 → 짧게 돌려 학습되는지 확인 |
| **4** | **Claude** | 사용자가 알려준 **학습 서버 스펙**에 맞춰 `B` / `--gpus` / worker 수 결정 → `tune_batch.py`로 실측 |
| **5** | **Claude** | 본 학습 시작. 팀이 휴리스틱 봇을 만들어 오면 **`ScriptedOpponent`로 상대 풀에 추가**하고 재개 |

각 단계의 구체적 절차·체크리스트·판정 기준은 **`FINALS_PLAYBOOK.md`** 에 있다.
**작업 시작 전에 반드시 읽어라.**

## 접근 방식

**self-play PPO + 배치 GPU 환경.** 게임 수천 판을 텐서 하나로 동시에 굴려
데이터를 모으고, **상대 풀**(직접 짠 휴리스틱 봇 + 과거 자기 자신의 스냅샷)과
겨루면서 실력을 올린다. 예선에서 이 방식으로 학습시킨 봇이 실제로 동작했다.
`rlkit/`이 이 루프 전체(PPO, GAE, 상대 풀, 멀티 GPU, 체크포인트, 페이즈 스케줄,
로깅)를 담당한다.

제출 형식은 예선 기준으로 "심판과 stdin/stdout으로 통신하는 단일 파일, torch 없이
numpy 순전파"였다. **본선에서 반드시 재확인할 것.**

## 이 디렉토리 지도

```
CLAUDE.md            ← 지금 읽고 있는 파일 (환경 블록을 여기서 채운다)
FINALS_PLAYBOOK.md   ← 5단계 절차서. 작업 시작 전에 읽을 것
PORTING_GUIDE.md     ← 1단계: 참조 시뮬레이터 → 배치 GPU 환경 이식법
tune_batch.py        ← 배치 크기 B 실측 튜닝 (4단계)
rlkit/               ← 게임 무관 학습 프레임워크 (완성/검증됨). README.md 참고
  interfaces.py      ← 계약: Task / Policy / ScriptedOpponent. 여기만 구현하면 된다
  parity.py          ← 참조 구현 vs 배치 env 정합성 하네스
examples/
  toy_duel.py        ← 템플릿. 이 파일을 복사해서 게임만 갈아끼운다
  toy_duel.yaml      ← 설정 파일 예시
  nypc2026.py        ← 예선 게임을 rlkit에 꽂은 참고 구현 (예선 저장소에서만 동작)
test_rlkit.py        ← 14개 유닛/E2E 테스트
test_rlkit_dist.py   ← 멀티 GPU 랭크 일치 테스트 (NCCL 불필요)
test_rlkit_nypc.py   ← 예선 게임 통합 테스트 (예선 저장소 밖에서는 자동 SKIP)
```

이 폴더에는 머신 고유 정보(파이썬 경로, GPU 개수, 스레드 수)가 **어디에도 적혀
있지 않다.** 다른 데스크탑·다른 학습 서버로 그대로 옮겨 쓰기 위해서다. 유일한
출처는 위 [환경] 블록이고, 그건 사용자가 알려준다.

## Claude에게

1. **`FINALS_PLAYBOOK.md`를 먼저 읽어라.** 단계별 절차, 판정 기준, 진단표가 있다.
2. **`rlkit/`은 건드리지 마라.** 검증된 코드다. 새 게임은 `examples/toy_duel.py`를
   복사해 고치는 방식으로 만든다. rlkit에 버그가 있다고 판단되면 먼저 말해라.
3. **규칙을 추측하지 마라.** 규칙 문서나 참조 구현이 없으면 사용자에게 요청한다.
   참조 구현이 있으면 그것이 규칙의 최종 근거다.
4. **1단계 결과물은 정합성 검증까지다.** `rlkit.parity.run`이 통과하지 않은 배치
   환경으로 다음 단계에 넘어가지 마라. 여기서 틀리면 뒤가 전부 무의미하다.
5. **속도가 곧 실력이다.** 완벽한 설계보다 빨리 학습을 시작하는 것이 중요하다.
   기능을 추가하기 전에 "이게 남은 시간 안에 승률을 올리는가"를 먼저 따져라.
6. **실제로 돌려보고 확인하라** — `--smoke`, 짧은 학습, 테스트. "될 것 같다"로
   넘어가면 나중에 시간을 두 배로 쓴다.
7. 모든 파이썬 명령은 위 [환경] 블록의 인터프리터로 실행한다.
